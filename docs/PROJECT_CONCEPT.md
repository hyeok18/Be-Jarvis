# 반응과 크리에이터 방문 근거로 보는 맛집 지도

> 제품의 상세 구현 범위와 수용 기준은 루트의 [`PRD.md`](../PRD.md)를 따른다.

## 문제

평균 별점은 취향 차이와 조작 가능성을 한 숫자 안에 숨긴다. 긴 리뷰나 영수증 인증을 요구하면 평소 리뷰를 쓰지 않는 사용자는 참여하지 않고, 인증 장벽을 낮추기만 하면 댓글·반응 작업 계정이 공개 결과를 오염시킬 수 있다. 유명 맛집 탐방 크리에이터의 방문 기록도 여러 영상에 흩어져 있어 지도에서 비교하기 어렵다.

## 제품 가설

사용자가 지도에서 다음 세 가지 근거를 서로 섞지 않고 볼 수 있다면 더 빠르고 정직하게 식당을 고를 수 있다.

- 방문 증명을 통과한 사용자의 `좋아요`, `그냥 그래요`, `싫어요` 분포
- 사용자의 취향·제외 음식·과거 만족도를 반영한 `나와의 매칭도`
- 관리자가 장소를 확인한 맛집 탐방 크리에이터의 개별 YouTube 영상과 최신 구독자 수

세 근거를 하나의 종합점수나 별점으로 합치지 않는다. 구독자 수는 영향력 신호일 뿐 식당 품질이나 영상 내용의 진실을 보증하지 않는다.

## 반응 원칙

- 공개 반응은 `좋아요`, `그냥 그래요`, `싫어요` 세 가지뿐이다.
- 사용자는 식당마다 현재 반응 하나를 한 번의 탭으로 남기거나 바꿀 수 있다.
- 공개 화면은 각 반응의 건수와 분포만 보여주며 평균, 긍정점수, 순위를 계산하지 않는다.
- 방문 증명 없는 반응은 개인 취향 학습에는 사용할 수 있지만 공개 집계에서는 제외한다.
- 의심 반응은 조작으로 단정하거나 즉시 삭제하지 않고 `held` 상태로 격리한다.
- P0에는 공개 자유서술 댓글을 두지 않아 댓글 작업의 공격 면적을 줄인다.

## 방문 증명 전략

영수증 업로드를 기본값으로 쓰지 않는다. 식당 근처에서 한 번 탭하는 위치 체크인을 P0 기본 증명으로 사용한다.

- 서버가 식당과의 거리 120m 이내, 위치 정확도 100m 이하를 확인한다.
- 성공한 체크인은 24시간 동안 해당 식당의 공개 반응 자격으로 쓴다.
- 원본 위도·경도와 브라우저 GPS 응답은 저장하거나 로그에 남기지 않는다.
- 위치 권한을 거부하면 반응은 개인 기록으로만 저장되고 공개 집계에는 반영되지 않는다.
- 영수증은 반복 위험이나 위치 스푸핑이 의심되는 경우의 선택적 추가 증명 후보로만 검토한다.

이 방식은 실제 식사까지 완벽히 증명하지 않는다. 제품은 `방문 가능성이 높은 반응`이라고 표현하고, 단일 인증 수단 대신 계정·거리·시간·행동 신호를 겹쳐 비용을 높인다.

## 반응 작업 방어 전략

- 로그인 계정과 유효한 방문 증명이 있어야 공개 집계 후보가 된다.
- 사용자·식당당 현재 반응 하나만 허용하고 모든 변경을 별도 감사 이벤트로 남긴다.
- 짧은 시간의 반복 요청, 증명 토큰 재사용, 불가능한 이동, 식당별 반응 급증, 계정 군집을 위험 신호로 기록한다.
- 위험 신호가 있는 반응은 우선 `held`로 보내고 마지막 정상 공개 집계를 유지한다.
- 한 신호만으로 사람을 작업 계정이라고 단정하지 않으며 관리자 검토와 복구 경로를 둔다.
- 원본 IP는 저장하지 않는다. 운영상 필요하면 일별 salt를 쓴 짧은 해시를 최대 7일만 보관한다.

## 크리에이터 방문 근거 원칙

- YouTube HTML을 scraping하지 않고 공식 YouTube Data API만 사용한다.
- 채널 allowlist의 업로드 목록을 증분 동기화하고 영상·채널 메타데이터로 장소 후보를 만든다.
- 장소 후보는 관리자가 식당과의 일치를 확인하기 전까지 공개하지 않는다.
- 확인된 개별 영상에는 채널명, 영상 제목, 게시일, 출처 링크, 최신 구독자 수를 함께 표시한다.
- 구독자 수가 공개된 근거끼리는 원본 구독자 수 내림차순으로 정렬할 수 있지만 파생 신뢰점수, 등급, 식당별 합산값은 만들지 않는다.
- 숨김 구독자 수는 0이 아니라 `알 수 없음`으로 처리한다.
- 사용자 승인 없는 YouTube API 데이터는 30일 안에 새로고침하거나 삭제하고, 오래된 근거는 공개에서 제외한다.

## 개인 매칭 원칙

- 안 먹는 음식은 hard exclusion으로 먼저 적용한다.
- 초기에는 사용자가 직접 선택한 맛·가격·거리·분위기 선호를 사용한다.
- 데이터가 쌓이면 비슷한 사용자 반응과 과거 방문 만족도를 보조 신호로 추가한다.
- 공개 반응 분포와 개인 매칭 계산은 분리한다. 다른 사용자의 공개 반응 가중치를 사람별 신뢰점수로 바꾸지 않는다.
- 매칭도가 낮거나 데이터가 부족한 이유를 사용자에게 설명한다.

## 24시간 MVP

1. 성수동 식당 30곳 지도와 목록
2. 세 반응 건수·분포와 데이터 부족 상태
3. 위치 체크인 기반 공개 반응 자격
4. 증명 없는 개인 반응과 counted-only 공개 집계 분리
5. 위험 반응 보류 상태와 마지막 정상 집계
6. 로컬 취향 기반 나와의 매칭도
7. 확인된 크리에이터 영상 근거와 구독자 원값 표시
8. 지도 실패 시 목록, YouTube 실패 시 마지막 정상 데이터 fallback

댓글, 장문 리뷰, 영수증 OCR, 자동 장소 공개, 별점과 모든 형태의 종합점수는 P0 범위가 아니다.
