## 1. 이번 작업의 목표

- 해결하려는 문제: 메인 화면에 실제 Kakao 지도와 식당 선택·카테고리·크리에이터 방문 레이어가 연결되어 있지 않다.
- 세션 범위: 합성 fixture 기반 지도 탐색 컴포넌트, Kakao JavaScript SDK 연결, 목록 fallback, 메인 화면 통합, 반응형 검증.
- 완료 조건: 카드·마커·필터·레이어가 동기화되고 SDK 실패 시 목록이 유지되며 lint·typecheck·test·build와 390px·1440px 검증이 통과한다.
- 범위 밖 항목: 실제 30곳 DB 데이터, YouTube API 동기화, 위치 체크인, 반응 생성, Vercel 배포.

## 2. 무엇을 만들었는가

- 서버 컴포넌트인 메인 페이지에서 합성 식당·counted 반응 요약·공개 가능한 confirmed 크리에이터 근거를 지도 탐색기에 전달한다.
- 클라이언트 경계 안에 카테고리 필터, 크리에이터 방문 전용 보기, 식당 카드, Kakao 지도와 모바일 지도 접기 기능을 구현했다.
- 카드 선택과 지도 마커 선택을 양방향으로 동기화하고 일반·크리에이터·선택 마커를 서로 다른 색으로 표시한다.
- 공개 가능한 confirmed 영상의 채널·제목·구독자 원값·영상일·API 기준일·YouTube 원본 링크를 카드와 지도 정보창에 표시한다.
- Kakao SDK 키 누락·스크립트 오류·초기화 오류·8초 응답 지연 시 주소·반응·카카오맵·YouTube 링크를 유지하는 fallback으로 전환한다.
- 공개 화면에는 별점이나 파생 크리에이터 점수를 추가하지 않고 합성 데이터 고지를 유지한다.

## 3. 무엇이 문제였고 어디에서 막혔는가

- 문제: WU-07의 문서상 선행 작업인 WU-06이 아직 완료되지 않았다.
- 문제: Kakao SDK 전역 타입이 없어 초기 typecheck가 실패했고, 지도 초기화 effect의 동기 상태 변경이 React lint 규칙에 걸렸다.
- 문제: `127.0.0.1` 대체 도메인은 Next 개발 서버의 출처 차단 때문에 실패 주입에 사용할 수 없었다.
- 해결 후 남은 영향: 코드와 AC 검증은 현재 mock 셸에서 통과했지만 문서상 선행 작업인 WU-06 최종 계약과 통합하기 전까지 상태를 진행 중으로 유지한다.

## 4. 어떻게 해결했는가

- 메인 페이지는 서버 컴포넌트로 유지하고 지도 상호작용만 독립 클라이언트 컴포넌트에 격리했다.
- 프로젝트에서 쓰는 Kakao SDK 범위만 최소 전역 타입으로 선언하고, 지도 생성은 취소 가능한 `requestAnimationFrame` 안에서 수행했다.
- 마커 이벤트는 재생성·언마운트 시 제거하고, 정보창 내용은 문자열 HTML 대신 DOM `textContent`로 생성했다.
- SDK 실패는 명시적 오류 콜백과 8초 타임아웃으로 처리하고 fallback 렌더링은 단위 테스트로 검증했다.
- 환경 파일을 수정하지 않고 빌드 프로세스에서만 Kakao 키를 비운 별도 production 서버를 3001번 포트로 실행해 실제 키 누락 fallback을 검증한 뒤 정상 키 빌드로 복구했다.
- 브라우저 검증 도구가 없는 환경에서는 앱 내 브라우저로 실제 localhost 화면을 검증했다.
