# 개발일지 인덱스

새 세션은 이 표에서 자신의 담당 범위에 `진행 중` 또는 `막힘`이 있는지 먼저 확인한다. 없다면 선행 조건이 완료된 가장 높은 우선순위의 `다음` 작업을 시작한다. 각 작업 단위의 상세 상태와 재개 지점은 연결된 최신 개발일지를 기준으로 한다.

| 작업 단위 | 제목 | 담당 | 상태 | 최신 기록 | 개발일지 | 다음 작업 또는 재개 지점 |
|---|---|---|---|---|---|---|
| WU-00 | 작업 단위·개발일지 운영체계 | 공통 | 완료 | 2026-08-25 | [기록](./2026-08-25_WU-00_development-governance.md) | WU-01 앱 셸과 품질 게이트 |

## 상태 갱신 규칙

- 작업 시작 시 해당 행을 추가하거나 갱신하고 `진행 중`으로 표시한다.
- 외부 정보, 권한, 사용자 결정 없이는 진행할 수 없으면 `막힘`과 정확한 재개 조건을 적는다.
- 구현·테스트·문서화가 완료 게이트를 통과한 뒤에만 `완료`로 바꾼다.
- 미완료 단위는 같은 일지의 `세션 업데이트`에 이어 기록한다.
- 최신 기록 날짜, 링크, 다음 작업 또는 재개 지점을 항상 함께 갱신한다.
- 개발일지를 삭제하거나 이전 실패 기록을 지우지 않는다.
- 팀 병렬 작업이 아니라면 `다음` 단위는 하나만 유지한다.
