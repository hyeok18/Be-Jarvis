# 개발 우선순위와 작업 단위

이 문서는 `PRD.md`의 24시간 MVP를 구현 가능한 작업 단위로 나눈 실행 보드다. 상세 제품 계약과 수용 기준은 `PRD.md`가 우선한다.

## 1. 운영 원칙

- 한 Codex 세션은 작업 단위 하나만 구현한다.
- `진행 중` 또는 `막힘` 단위가 있으면 최신 개발일지를 읽고 먼저 이어간다.
- 새 단위는 모든 선행 조건이 `완료`일 때만 시작한다.
- 각 단위는 연결된 AC, 자동 테스트, 수동 검증을 모두 통과해야 `완료`다.
- 팀 병렬 개발은 허용하지만 공유 파일 담당을 먼저 정하고 각 세션은 한 단위만 활성화한다.
- P0 필수 작업과 WU-19 릴리스 게이트를 완료하기 전에는 PRD의 선택 범위를 시작하지 않는다.
- 상태는 `대기`, `다음`, `진행 중`, `막힘`, `완료`만 사용한다.

## 2. 우선순위 기준

| 우선순위 | 의미 | 처리 규칙 |
|---|---|---|
| P0 | 시연 흐름, 핵심 결과 정확성, 데이터·보안 안전에 필수 | 완료 전 선택 기능 금지 |
| P1 | P0 완료 후 품질 또는 운영 편의를 높임 | WU-19 통과 후에만 새 작업 단위로 등록 |
| P2 | 해커톤 MVP 제외 또는 향후 확장 | PRD 변경 승인 전 구현 금지 |

P0 안에서는 다음 순서로 판단한다.

```text
공유 계약과 품질 게이트
→ 원본 데이터·권한
→ 재현 가능한 점수 계산
→ 최소 공개 사용자 흐름
→ 관리자 입력·분석 운영
→ 장애 복구·발표 백업
→ 접근성·보안·배포
→ 전체 리허설
```

## 4. 작업 단위별 완료 조건

### WU-00 — 작업 단위·개발일지 운영체계

산출물:

- `AGENTS.md`
- `docs/DEVELOPMENT_PRIORITY.md`
- `docs/DEVELOPMENT_LOG_TEMPLATE.md`
- `docs/development-logs/INDEX.md`
- WU-00 개발일지

완료 조건:

- 세션 시작, 한 단위 활성화, 완료 게이트, 미완료·막힘 처리, 다음 세션 재개 규칙이 명시됨
- PRD AC-01~AC-28이 WU-01~WU-19에 빠짐없이 연결됨
- 다음 작업이 WU-01로 하나만 지정됨

### WU-01 — Next.js 앱 셸과 품질 게이트

산출물:

- Next.js App Router + TypeScript + Tailwind CSS 프로젝트
- `.env.example`, 기본 `.gitignore`, 공통 레이아웃과 오류 경계
- lint, typecheck, test, build 스크립트와 최소 smoke test
- PRD·AGENTS의 Supabase DB migration/RLS와 Vercel 환경·배포 플러그인 실행 계약

완료 조건:

- 빈 환경에서도 설치와 로컬 실행 절차가 재현됨
- `.env.example`에는 PRD 8장의 변수 이름만 있고 실제 값은 없음
- 네 가지 필수 자동 검증 명령이 모두 성공함
- Vercel 배포를 막는 로컬 파일 의존성이 없음
- 플러그인으로 현재 Supabase·Vercel 프로젝트 상태를 읽기 전용 확인하고, 새 리소스 생성 조건과 후속 WU를 기록함

### WU-02 — 도메인 타입·알고리즘 설정·mock 계약

산출물:

- 식당, 다면 원본 리뷰, 반응 집계, 분석 실행, 리뷰 분석, 식당 점수의 TypeScript 계약
- 로컬 선호, 매칭 근거와 공개/개인화 경계를 포함한 버전 있는 `algorithm_config`
- 화면과 서버가 함께 사용할 고정 공개·매칭 mock·fixture

완료 조건:

- PRD 데이터 모델과 타입 이름·필수값이 일치함
- 점수 공식, 반올림, 동점 정렬 계약 테스트가 존재함
- 맛·청결·서비스 60:20:20, 커뮤니티 상하한, 매칭 재정규화·hard exclusion 테스트가 존재함
- 리뷰어 키·유사도 변경이 공개 점수에 영향을 주지 않는 테스트가 존재함
- 원본 데이터 타입과 파생 분석 타입이 분리됨
- A1·B1·B2가 같은 fixture로 독립 개발할 수 있음

### WU-03 — Supabase 스키마·RLS·관리자 권한 기반

산출물:

- PRD 8장의 다면 별점·반응 집계를 포함한 테이블, 제약, 인덱스, migration
- RLS 정책과 필요한 명시적 권한
- 서버·브라우저 Supabase 클라이언트 분리와 관리자 검증 함수
- Supabase 플러그인으로 선택·비용 확인된 전용 project/branch에 migration 적용

완료 조건:

- 원본 리뷰와 파생 결과가 별도 테이블에 저장됨
- 공개 사용자는 허용된 읽기만 가능하고 쓰기·로그·설정은 차단됨
- 비로그인·일반 사용자·관리자 권한 테스트가 통과함
- secret/service-role 키가 클라이언트 코드에 포함되지 않음
- security/performance advisor 경고 검토와 TypeScript DB 타입 생성이 완료됨

### WU-04 — 성수동 식당·합성 리뷰 seed와 시연 fixture

산출물:

- Kakao 장소 검색 근거를 가진 성수동 식당 30곳 seed
- 식당당 맛·청결·서비스 별점과 반응 집계를 가진 합성 리뷰 20개, 총 약 600개 fixture
- 매칭 검증용 합성 선호·제외 음식·방문 만족도 fixture
- 정상·급증·유사·편향·복합 패턴과 별도 시연 CSV
- seed 버전, 생성 규칙, 재실행·비활성화 절차

완료 조건:

- 외부 서비스의 실제 리뷰가 포함되지 않음
- 동일 seed를 반복 실행해도 `external_id` 중복이 생기지 않음
- 식당·리뷰 수와 패턴 분포 검증이 자동화됨
- 잘못된 seed를 삭제 대신 비활성화하고 재생성할 수 있음

## 6. 상태 변경 규칙

- 작업을 시작하면 해당 행을 `진행 중`으로 바꾸고 개발일지를 생성하거나 갱신한다.
- 선행 조건이나 외부 입력 없이는 진행할 수 없으면 `막힘`으로 바꾸고 정확한 재개 조건을 적는다.
- 완료 게이트를 모두 통과한 뒤에만 `완료`로 바꾸고 증거를 기록한다.
- 팀 병렬 작업이 아니라면 `다음` 상태는 항상 하나만 유지한다.
- 새로운 필수 작업이 발견되면 기존 ID 사이에 끼우지 말고 다음 빈 `WU-XX`를 부여한다.
- 작업 단위를 합치거나 쪼갤 때 대상 AC, 선행 조건, INDEX, 관련 개발일지를 함께 갱신한다.
- 선택 범위는 WU-19 완료 후 별도 P1 작업 단위로 등록한다.

4. 공식 CLI로 migration 파일을 만든 뒤 PRD의 다면 별점·반응 집계·분석 테이블과 제약·인덱스를 구현한다.
