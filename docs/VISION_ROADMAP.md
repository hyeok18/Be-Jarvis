# 제품 비전과 로드맵

현재 구현 계약과 수용 기준은 루트의 [`PRD.md`](../PRD.md)가 우선한다. 이 문서는 별점 폐지 이후의 장기 방향과 24시간 MVP 경계를 설명한다.

## 1. 제품 비전

사용자는 식당을 고를 때 다음 세 질문에 각각 다른 근거로 답을 얻는다.

1. 실제 방문을 어느 정도 확인한 사용자들은 어떤 반응을 남겼는가?
2. 이 식당은 내 취향과 안 먹는 음식에 얼마나 맞는가?
3. 내가 참고할 만한 맛집 탐방 크리에이터가 이 식당을 영상에서 소개했는가?

세 질문을 하나의 종합점수로 합치지 않는다. 공개 반응은 세 방향의 분포, 개인화는 나와의 매칭도, 크리에이터 근거는 개별 영상 출처로 각각 보여준다.

## 2. 확정된 제품 원칙

| 영역 | 원칙 |
|---|---|
| 평가 입력 | `좋아요`, `그냥 그래요`, `싫어요`만 허용한다. |
| 공개 표시 | 검증 반응 건수와 분포만 제공하고 평균·별점·종합점수를 만들지 않는다. |
| 방문 증명 | 위치 체크인을 기본으로 하고 증명 없는 반응은 개인 취향에만 사용한다. |
| 어뷰징 | 인증, 1인 1현재반응, 방문 토큰, rate limit, 보류 큐를 조합한다. |
| 개인화 | 공개 반응과 독립된 취향·유사 사용자·내 이력으로 매칭도를 계산한다. |
| 크리에이터 | 공식 YouTube Data API의 개별 영상과 최신 구독자 수를 출처로 제시한다. |
| 공신력 | 구독자 수가 큰 개별 출처를 먼저 보여주되 자체 공신력 점수나 식당 점수로 변환하지 않는다. |
| 공개 글 | P0에는 자유서술 리뷰·댓글을 만들지 않는다. |

## 3. 단계별 우선순위

### P0 — 24시간 MVP

- 별점·평균·종합점수·리뷰 신뢰도 완전 제거
- 세 반응의 counted-only 집계와 데이터 부족 상태
- Supabase Auth와 사용자·식당당 한 개 현재 반응
- 위치 체크인 방문 증명과 원본 좌표 비저장
- 증명 없는 반응의 개인 전용 처리
- rate limit과 위험 반응 `held` 처리
- 브라우저 로컬 취향과 나와의 매칭도
- YouTube 채널 allowlist, 공식 API 동기화, 관리자 영상-식당 확인
- 개별 영상 근거·최신 구독자 수·hidden/stale 처리
- Kakao 지도와 크리에이터 방문 레이어

P0의 공개 화면은 합성 fixture로 검증한다. 실제 영상 메타데이터를 연결하더라도 관리자 확인 전에는 지도에 공개하지 않는다.

### P1 — 증명 강화와 운영 도구

- 매장 QR/NFC 체크인
- 위험 사용자에게만 영수증·예약·결제 증명 요청
- 보류 반응 관리자 검토와 이의 복구
- 계정 기반 취향 동기화·삭제·내보내기
- 실제 반응 데이터를 이용한 유사 사용자 매칭 평가
- 채널 운영자 요청에 따른 API 데이터 삭제 절차

### P2 — 확장과 실험

- 지역 확장과 현재 위치 중심 탐색
- 시간대·동행·예산·거리 문맥 추천
- 어뷰징 군집 탐지와 운영 지표
- 크리에이터 취향을 사용자가 직접 선택하는 개인화
- 정책 승인을 먼저 받은 경우에만 YouTube 데이터 기반 파생 지표 검토

## 4. 방문 증명 전략

완벽한 방문 인증을 약속하지 않는다. `편한 반응`과 `공개 집계 자격`을 분리한다.

```text
한 번 탭 반응
├─ 방문 증명 있음 → moderation 통과 후 공개 분포
└─ 방문 증명 없음 → 개인 취향 기록만
```

영수증은 모든 사용자에게 강제하지 않는다. 위치 체크인은 부담이 낮지만 조작 가능성이 있으므로 계정·속도·이동·집중 패턴을 함께 본다. 의심 상황에서만 더 강한 증명을 요청한다.

## 5. 어뷰징 대응 원칙

- 공격을 100% 막는다고 주장하지 않고 공개 집계 오염 속도를 낮춘다.
- 공개 텍스트 입력을 만들지 않아 복제 댓글과 홍보 문구 공격면을 줄인다.
- 위험 신호는 삭제가 아니라 보류 상태를 만든다.
- IP 원문과 안정적 기기 지문을 장기 저장하지 않는다.
- 반응 변경과 moderation을 append-only 이벤트로 재현한다.
- 임계값 변경은 버전을 올리고 합성 공격 fixture로 회귀 검증한다.

## 6. 크리에이터 데이터 원칙

- HTML scraping, 영상·자막 다운로드, 댓글 수집을 하지 않는다.
- YouTube Data API의 공개 메타데이터를 30일 안에 새로고침하거나 삭제한다.
- 구독자 수 비공개는 0이 아니라 `알 수 없음`이다.
- 자동 장소 후보는 사람의 확인 전까지 공개하지 않는다.
- 구독자 수는 개별 출처의 최신 원값으로 표시·정렬할 뿐 합산·변환하지 않는다.
- YouTube 출처, 원본 영상 링크, 메타데이터 기준 시각을 함께 보여준다.

## 7. 성공 지표

| 단계 | 지표 |
|---|---|
| P0 | 반응 완료 탭 수 1회, counted-only 집계 테스트 통과, 별점 금지 검사 0건, 발표 3회 성공 |
| P1 | 위치 체크인 완료율, 공개 반응 전환율, held 오탐 복구시간, 중복 공개 반응 0건 |
| P2 | 매칭순위 선택 후 만족도, 추천 다양성, creator 출처 클릭률, 어뷰징 대응시간 |

반응의 `좋아요 비율` 자체를 북극성 지표로 쓰지 않는다. 제품 성공은 반응 완료율, 검증 품질, 매칭 후 만족도, 근거 활용도로 판단한다.
