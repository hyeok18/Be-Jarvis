# 비자비스(Be Jarvis) 24시간 MVP 제품 요구사항 문서

| 항목 | 내용 |
|---|---|
| 문서 상태 | 인터뷰 완료·구현 준비 완료 |
| 작성일 | 2026-08-24 |
| 제품명 | 비자비스(Be Jarvis), 가칭 |
| MVP 대상 | 만 18세 이상 한국 국적자의 미국 관광 목적 ESTA 신청 준비 |
| 배포 목표 | 외부 사용자가 링크로 체험할 수 있는 공개 데모 |
| 구현 기준 모델 | GPT-5.6 Luna가 추가 제품 결정을 요구하지 않고 구현 가능한 수준 |

## 1. 제품 요약

비자비스는 한국어 사용자가 미국 ESTA 신청에 필요한 텍스트 정보를 단계별로 이해하고 작성하도록 돕는 민간 신청 준비 서비스다. 사용자는 한국어 설명과 예시를 보며 정보를 입력하고, 선택적으로 AI 검토를 실행한 뒤, 공식 ESTA 신청서 순서대로 정리된 값을 항목별로 복사할 수 있다.

비자비스는 ESTA 신청을 대신 제출하거나 승인 가능성을 판정하지 않는다. 사용자는 여권·셀피 업로드, 이메일 인증, 결제 및 최종 제출을 미국 관세국경보호청(CBP)의 공식 ESTA 사이트에서 직접 수행한다.

24시간 MVP는 실제 개인정보를 받는 운영 서비스가 아니라 가상 정보로만 체험하는 공개 데모다.

## 2. 해결하려는 문제

한국인 여행자는 공식 ESTA 신청 과정에서 다음과 같은 어려움을 겪을 수 있다.

- 영문 항목명의 의미와 입력 형식을 이해하기 어렵다.
- 여권, 주소, 고용 및 미국 내 연락처 정보를 어떤 형식으로 입력할지 헷갈린다.
- 여러 단계에서 누락이나 앞뒤가 맞지 않는 답변이 발생한다.
- 비공식 대행 사이트와 미국 정부 공식 사이트를 구분하기 어렵다.
- ESTA 대상이 아닌데도 신청을 계속하거나, 반대로 신청 가능한데 불필요하게 방문비자를 알아볼 수 있다.
- 전체 정보를 작성한 뒤 공식 사이트의 어느 항목에 옮겨야 하는지 다시 찾아야 한다.

## 3. 제품 목표

### 3.1 핵심 목표

1. 사용자가 도움 없이 ESTA 준비 과정을 끝까지 완료하게 한다.
2. 공식 ESTA 신청서와 같은 순서로 정보를 수집한다.
3. 각 항목에 한국어 설명, 입력 예시, 형식 검증을 제공한다.
4. 결과 화면에서 공식 항목명과 입력값을 항목별로 복사할 수 있게 한다.
5. AI가 누락·형식 오류·답변 간 불일치를 검토하되, 사실을 임의로 바꾸지 못하게 한다.
6. 서비스가 미국 정부나 법률 대리인으로 오인되지 않게 한다.

### 3.2 성공 지표

핵심 지표는 `독립 완료율`이다.

- 가상 정보로 테스트하는 성인 사용자 5명 중 4명 이상이 외부 도움 없이 시작부터 결과 화면까지 완료한다.
- 완료의 정의는 사전 확인, 모든 필수 입력, 최종 검토, 결과 카드 열람을 마치는 것이다.
- 테스트 중 공식 신청서에 대응되는 필수 텍스트 항목의 치명적 누락이 0건이어야 한다.
- AI가 제안한 값이 사용자 승인 없이 최종 결과에 반영되는 경우가 0건이어야 한다.

### 3.3 비목표

다음은 24시간 MVP에서 구현하지 않는다.

- ESTA 자동 제출 또는 공식 사이트 자동 입력
- 승인 가능성 점수, 승인 보장 또는 법률 자문
- B1/B2 방문비자 신청서 작성
- 미성년자, 가족, 단체 신청
- 회원가입, 로그인, 결제, 데이터베이스 저장
- 실제 여권 또는 셀피 업로드·OCR·검증
- 이메일 인증, ESTA 수수료 결제, 신청 상태 조회
- 실제 개인정보를 사용한 공개 운영
- 다국가·다국어 비자 지원
- 상담원 연결 및 신청 대행

## 4. 대상 사용자

### 4.1 1차 사용자

- 대한민국 국적자
- 만 18세 이상
- 본인의 신청을 준비하는 사람
- 미국을 관광 목적으로 90일 이하 방문하려는 사람
- 한국어로 설명을 읽고 모바일 또는 PC 웹을 사용하는 사람
- ESTA 신청을 새로 준비하며 공식 양식의 영문 표현이 낯선 사람

### 4.2 지원하지 않는 사용자

- 만 18세 미만 신청자 또는 미성년자를 대신 작성하는 보호자
- 한국 외 국적자
- 90일 초과 체류 예정자
- 취업, 정규 학업, 이민, 언론 활동 등 관광이 아닌 목적의 방문자
- 가족·동행자 정보를 한꺼번에 작성하려는 사용자
- 실제 신청을 대신 제출해 줄 대행 서비스를 원하는 사용자

## 5. 핵심 제품 원칙

1. **정확성 우선:** 신원, 여권, 날짜 및 자격 질문은 AI가 자동 변경하지 않는다.
2. **한 화면 한 행동:** 토스·애플과 같이 현재 단계의 핵심 질문과 다음 행동만 강조한다.
3. **공식 사이트 우선:** 규정·수수료·필수 항목이 충돌하면 CBP 공식 사이트를 최종 기준으로 한다.
4. **민간 서비스 표시:** 미국 정부 로고, ESTA 로고, 문장(紋章) 또는 공식 사이트와 혼동될 표현을 사용하지 않는다.
5. **데모 안전성:** 실제 개인정보 입력을 금지하고 가상 정보 사용을 반복 안내한다.
6. **사용자 통제:** AI 검토는 선택이며, 모든 변경은 사용자가 직접 승인한다.
7. **확장 가능한 스키마:** 국가·여행 목적·신청 양식별 질문을 설정 파일로 분리한다.

## 6. MVP 사용자 여정

```text
랜딩
  → 데모·비공식 서비스 안내 및 가상 정보 사용 동의
  → ESTA 사전 확인
      → 명백한 범위 외: 중단 + 공식 안내
      → 판단 필요: 경고 + 사용자 선택
      → 통과: 단계별 신청 정보 입력
  → 입력값 자체 검토
  → 선택적 AI 전체 검토 동의
      → AI 제안별 수락/거절
  → 공식 양식 순서의 복사 결과
  → 공식 ESTA 사이트를 새 탭으로 열기
  → 사진·이메일 인증·결제·최종 제출은 공식 사이트에서 진행
```

## 7. 화면 구성

### S01. 랜딩

목적은 5초 안에 서비스 역할과 한계를 이해시키는 것이다.

필수 요소:

- 가칭 로고 텍스트: `비자비스 Be Jarvis`
- 헤드라인: `복잡한 ESTA 정보, 한국어로 준비하고 항목별로 복사하세요.`
- 보조 문구: `미국 관광 목적 ESTA 신청에 필요한 텍스트 정보를 단계별로 정리하는 공개 데모입니다.`
- 1차 버튼: `가상 정보로 시작하기`
- 2차 링크: `어떻게 진행되나요?`
- 상단 또는 헤드라인 인접 배지: `공개 데모 · 실제 개인정보 입력 금지`
- 비공식 안내: `비자비스는 미국 정부 또는 CBP와 관련이 없는 민간 신청 준비 서비스입니다.`
- 공식 사이트 링크: `미국 정부 공식 ESTA 사이트`

### S02. 데모 동의

다음 항목을 모두 확인해야 진행할 수 있다.

- 실제 이름, 여권번호, 생년월일, 주소, 연락처를 입력하지 않는다.
- 이 서비스는 ESTA 신청·결제·제출을 대신하지 않는다.
- 결과는 공식 신청서에 옮기기 위한 연습용 초안이다.
- AI 검토는 나중에 별도로 선택할 수 있다.

필수 체크박스:

`실제 개인정보가 아닌 가상 정보만 입력하겠습니다.`

체크 전에는 `동의하고 시작` 버튼을 비활성화한다.

### S03. ESTA 사전 확인

한 화면에 한 질문을 표시한다. 상단에 `사전 확인 2/6`처럼 진행률을 보여준다.

질문 항목:

1. 대한민국 전자여권을 가지고 있는가?
2. 신청자 본인이 만 18세 이상인가?
3. 여행 목적이 관광·휴가·친지 방문 등 허용된 단기 방문인가?
4. 미국 체류 예정 기간이 90일 이하인가?
5. 현재 유효한 미국 방문비자를 소지하고 있지 않은가?
6. 귀국 또는 제3국행 계획이 있는가?

결과 유형:

- `PASS`: MVP 범위에 해당하며 계속 진행할 수 있음
- `STOP`: 국적, 나이, 목적, 체류 기간, 전자여권 등 명백한 범위 외 조건
- `REVIEW`: 과거 거절·입국 문제·특정 국가 방문 이력 등 개별 확인이 필요한 경우

`STOP` 화면 요구사항:

- `비자비스의 현재 ESTA 데모 범위에 해당하지 않습니다.`라고 표시한다.
- 이유를 한 문장으로 설명한다.
- B1/B2 등 적절한 경로를 단정하지 않고 미국 국무부와 CBP 공식 안내 링크를 제공한다.
- `처음부터 다시 확인` 버튼을 제공한다.

`REVIEW` 화면 요구사항:

- 자격을 확정하거나 불가로 판정하지 않는다.
- `공식 기준 또는 전문가 확인이 필요할 수 있습니다.`라고 표시한다.
- `공식 안내 확인`과 `위험을 이해하고 데모 계속`을 분리한다.

### S04. 단계별 정보 입력

입력 폼은 공식 ESTA 신청 순서를 따르며 다음 섹션으로 구성한다.

1. 신청자 및 여권 정보
2. 개인·연락처 정보
3. 부모 및 고용 정보
4. 여행 및 미국 내 정보
5. 비상 연락처
6. 자격·보안 질문

공통 UI:

- 모바일에서는 한 열, PC에서는 최대 두 열을 사용한다.
- 상단에 현재 섹션, 전체 진행률, `나가기`를 표시한다.
- 하단에 `이전`과 `저장하고 다음` 버튼을 고정한다.
- 필수 항목은 텍스트뿐 아니라 아이콘·보조 문구로 구분한다.
- 항목마다 한국어 질문, 공식 영문 항목명, 간단한 설명, 가상 예시를 제공한다.
- 입력 오류는 제출 시 한꺼번에 보여주지 않고 해당 필드 아래에 즉시 표시한다.
- 조건부 질문은 선행 답변에 따라 표시·숨김 처리한다.
- `이 항목이 어려워요` 버튼을 통해 AI 도움을 요청할 수 있다.

### S05. 입력값 검토

- 섹션별 완료 여부를 카드로 표시한다.
- 누락, 형식 오류, 날짜 관계 오류를 AI 호출 없이 먼저 검사한다.
- 오류 카드를 누르면 해당 필드로 이동한다.
- 필수 오류가 있으면 결과 생성을 차단한다.
- `AI로 전체 검토하기`와 `AI 없이 결과 보기`를 모두 제공한다.

### S06. AI 검토 동의 및 결과

AI 검토 실행 전 별도 모달 또는 화면에서 다음을 설명한다.

- 현재 작성한 전체 데모 신청 내용이 외부 AI 서비스로 전송된다.
- 검토 목적은 누락, 형식 오류, 번역 및 답변 간 불일치 탐지다.
- AI 제안은 사실 확인이나 법률 판단이 아니다.
- AI 검토 없이도 결과 화면으로 이동할 수 있다.

필수 버튼:

- `동의하고 AI 검토`
- `AI 검토 건너뛰기`

제안 카드 구성:

- 문제 유형과 심각도
- 해당 공식 항목명
- 사용자의 원래 값
- AI가 제안한 값
- 수정 이유
- `제안 반영` 및 `원문 유지`

모든 제안은 기본 미선택 상태다. 보안 질문, 신원 사실, 여권번호 및 날짜는 AI가 새 값을 만들어 제안할 수 없고 확인 필요 표시만 할 수 있다.

### S07. 복사 결과

결과는 공식 ESTA 항목 순서와 같은 섹션으로 제공한다.

각 결과 카드 구성:

- 공식 영문 항목명
- 한국어 의미
- 공식 사이트에 입력하거나 선택할 최종 값
- `복사` 버튼
- 값의 출처: `사용자 입력` 또는 `사용자가 승인한 AI 제안`

동작 요구사항:

- 텍스트·숫자·날짜·선택값 모두 항목별 복사가 가능해야 한다.
- 날짜처럼 공식 사이트에서 나누어 선택하는 값은 `월`, `일`, `연도`를 각각 표시한다.
- 주소는 줄별로 분리해 보여준다.
- 복사 성공 시 `복사됨` 피드백을 2초간 표시한다.
- 섹션 단위 접기·펼치기를 제공하되 첫 섹션은 펼친 상태다.
- 진행용 체크박스 `공식 사이트에 입력함`을 카드마다 제공한다. 이 체크 상태도 현재 탭에서만 유지한다.
- `공식 ESTA 사이트 열기`는 새 탭으로 열고 `rel="noopener noreferrer"`를 사용한다.
- 사진, 이메일 인증, 결제, 최종 제출은 공식 사이트에서 해야 한다는 체크리스트를 결과 상단과 하단에 표시한다.

## 8. 수집 데이터 스키마

정확한 필수 여부와 공식 선택지는 구현 당일 CBP의 현재 신청서와 대조한다. 아래는 MVP가 지원해야 하는 최소 그룹이다.

## 9. 입력 및 검증 규칙

### 9.1 일반 규칙

- 모든 값의 앞뒤 공백을 제거한다.
- 빈 선택 항목은 빈 문자열이 아니라 `null`로 저장한다.
- 사용자가 입력한 원본과 정규화된 표시값을 구분한다.
- 영문 입력 필드는 허용 문자 규칙을 필드별로 명시한다.
- 이름은 임의 번역하지 않고 가상 여권의 기계판독영역 표기를 따르도록 안내한다.
- 이메일 확인 값은 이메일과 일치해야 한다.
- 전화번호는 국가번호와 본문을 분리한다.
- 여권 발급일은 만료일보다 앞서야 한다.
- 생년월일은 현재보다 과거여야 하며 MVP에서는 만 18세 이상이어야 한다.
- 체류 종료일을 받는 경우 시작일보다 늦고 총 체류가 90일 이하여야 한다.
- 조건부 필드가 숨겨질 때 기존 값은 사용자 확인 후 제거한다.

### 9.2 오류 문구 원칙

- `잘못되었습니다` 대신 무엇을 어떻게 바꿔야 하는지 말한다.
- 예: `여권 만료일은 발급일보다 뒤여야 합니다.`
- 예: `이메일 주소 두 개가 서로 다릅니다.`
- 예: `미국 체류 예정 기간이 90일을 초과해 현재 MVP 범위에서 진행할 수 없습니다.`

## 10. AI 기능 요구사항

### 10.1 기능 A: 필드 도움

사용자가 `이 항목이 어려워요`를 누르면 다음을 제공한다.

- 해당 항목을 묻는 이유에 대한 쉬운 한국어 설명
- 가상 정보 예시
- 입력 형식 예시
- 공식 안내가 필요한 경우 공식 링크

AI는 사용자의 사실을 추측해 채우지 않는다. 보안 질문에는 답변 방향을 추천하지 않는다.

### 10.2 기능 B: 전체 신청 검토

실행 조건:

- 사용자가 S06에서 별도 동의함
- 클라이언트 기본 검증을 통과함
- 전송 데이터가 데모 데이터임을 다시 확인함

검토 범위:

- 필수값 누락
- 형식 오류 가능성
- 서로 모순되는 답변
- 영문 주소·전화·직책 표기의 일관성
- 공식 항목과 값 유형의 불일치

검토 금지:

- ESTA 승인 가능성 예측
- 법률 자문
- 보안 질문 답변 추천
- 신원·여권·이력의 사실 생성
- 사용자가 제공하지 않은 값을 추측해 채우기
- 자동 변경

### 10.3 AI 응답 형식

AI 응답은 자유 텍스트가 아니라 다음 구조의 JSON이어야 한다.

```json
{
  "summaryKo": "검토 요약",
  "issues": [
    {
      "id": "issue-001",
      "fieldPath": "application.travel.usAddress.city",
      "severity": "error",
      "category": "format",
      "originalValue": "Newyork",
      "suggestedValue": "New York",
      "explanationKo": "도시명의 일반적인 영문 표기를 확인해 주세요.",
      "requiresUserConfirmation": true,
      "confidence": "medium"
    }
  ]
}
```

허용값:

- `severity`: `error`, `warning`, `info`
- `category`: `missing`, `format`, `consistency`, `translation`, `official-check`
- `confidence`: `low`, `medium`, `high`

서버는 스키마에 맞지 않는 응답을 거부하고 한 번만 재시도한다. 재시도도 실패하면 AI 검토를 건너뛰고 기본 결과를 제공한다.

### 10.4 모델 및 API

- 모델: `gpt-5.6-luna`
- API: OpenAI Responses API
- 권장 추론 수준: `low`
- `store: false`를 명시한다.
- API 키는 서버 환경 변수에서만 읽고 브라우저에 노출하지 않는다.
- 요청·응답 본문을 서버 콘솔 또는 파일 로그에 남기지 않는다.
- AI 오류가 전체 작성 흐름을 막지 않도록 한다.

## 11. 개인정보·보안·신뢰 요구사항

### 11.1 데모 데이터 정책

- 모든 주요 화면에 `공개 데모 · 실제 개인정보 입력 금지` 표시를 유지한다.
- 첫 진입 시 가상 정보 사용 동의가 필수다.
- `샘플 데이터 채우기` 기능을 제공해 실제 정보 입력 유인을 낮춘다.
- 실제 개인정보처럼 보이는 값의 자동 탐지는 신뢰할 수 없으므로 탐지 결과를 안전 보장으로 표현하지 않는다.

### 11.2 저장 정책

- 서버 데이터베이스, 파일, 쿠키 및 분석 도구에 신청값을 저장하지 않는다.
- 브라우저의 `sessionStorage`에만 현재 상태를 저장한다.
- 새로고침 후에는 복구한다.
- 탭을 닫으면 브라우저 정책에 따라 세션 데이터가 제거된다.
- `모든 데모 정보 삭제` 버튼으로 즉시 상태를 초기화할 수 있다.
- `localStorage`와 IndexedDB는 사용하지 않는다.

### 11.3 네트워크 및 로그

- AI 검토를 선택하지 않으면 신청값을 서버로 전송하지 않는다.
- AI 요청은 동일 출처의 서버 엔드포인트를 통해 전송한다.
- 서버 오류에는 입력값이나 외부 API 원문을 포함하지 않는다.
- 접근 로그에 쿼리 문자열로 신청값을 넣지 않는다.
- 분석 이벤트에는 필드 값 대신 단계명과 성공·실패 여부만 기록한다.
- HTTPS 배포를 필수로 한다.

### 11.4 필수 고지

다음 내용을 랜딩, AI 동의, 결과 화면에 맥락에 맞게 표시한다.

- 비자비스는 미국 정부, 국토안보부, CBP 또는 미국 국무부와 관련이 없는 민간 서비스다.
- ESTA는 비자가 아니라 비자면제프로그램을 통한 여행 허가다.
- 비자비스는 승인 또는 미국 입국을 보장하지 않는다.
- 신청 내용의 정확성과 공식 제출 책임은 사용자에게 있다.
- 최종 기준은 미국 정부 공식 사이트의 최신 안내다.
- 본 MVP는 실제 개인정보를 입력하면 안 되는 공개 데모다.

## 13. 비기능 요구사항

### 13.1 사용성

- 모바일 기준 360px 너비에서 가로 스크롤 없이 동작한다.
- 주요 버튼의 터치 영역은 최소 44×44px이다.
- 현재 단계와 남은 단계를 항상 확인할 수 있다.
- 한 화면에 동시에 표시하는 주요 결정 질문은 하나로 제한한다.
- 뒤로 이동해도 기존 답변이 유지된다.

### 13.2 접근성

- 키보드만으로 전체 흐름을 완료할 수 있다.
- 모든 입력에 연결된 `label`이 있다.
- 오류 메시지는 색상만으로 구분하지 않는다.
- 포커스 표시를 제거하지 않는다.
- 텍스트와 배경은 WCAG AA 수준의 대비를 목표로 한다.
- 복사 성공과 오류는 `aria-live`로 알린다.

### 13.3 성능

- 일반 모바일 네트워크에서 초기 핵심 화면이 3초 이내에 표시되는 것을 목표로 한다.
- AI 호출 전의 모든 입력·검증·복사 기능은 외부 API 없이 동작한다.
- AI 응답 대기 중 취소 또는 건너뛰기가 가능해야 한다.

### 13.4 신뢰성

- 알 수 없는 오류로 사용자의 작성 상태가 초기화되지 않아야 한다.
- 공식 스키마 버전과 최종 확인일을 코드 설정과 화면 하단에 표시한다.
- 공식 신청 항목이 변경됐을 때 UI 전체를 수정하지 않고 스키마 설정을 교체할 수 있어야 한다.

- 여행 서비스의 과도한 사진·일러스트보다 입력과 진행 상태를 우선

## 15. 기술 구현 가이드

현재 저장소의 Node.js 내장 HTTP 서버, 바닐라 HTML/CSS/JavaScript 및 OpenAI Responses API 구조를 재사용한다. 24시간 내 공개 데모 완성을 위해 데이터베이스와 프론트엔드 프레임워크 도입은 피한다.

- AI 제안 수락·거절 및 적용

### 15.4 API 계약

`POST /api/field-help`

```json
{
  "fieldId": "employment.jobTitle",
  "fieldLabelKo": "직책",
  "officialLabelEn": "Job Title",
  "currentValue": "가상 입력값",
  "isDemo": true
}
```

성공 응답:

```json
{
  "explanationKo": "현재 또는 이전 직장에서 사용한 직책을 입력하는 항목입니다.",
  "example": "MARKETING ASSISTANT",
  "warning": null
}
```

`POST /api/review`

```json
{
  "isDemo": true,
  "sourceVersion": "2026-08-24",
  "application": {},
  "explicitConsent": true
}
```

서버 검증:

- `isDemo !== true`이면 400 응답
- `explicitConsent !== true`이면 400 응답
- 허용된 신청 스키마 외 속성 제거 또는 요청 거부
- 본문 크기 상한 적용
- AI 결과를 지정 JSON 스키마로 재검증

### 15.5 설정 기반 질문 스키마

`esta-schema.js`의 각 필드는 다음 메타데이터를 가진다.

```js
{
  id: "applicant.passportNumber",
  section: "applicant",
  order: 120,
  labelKo: "여권번호",
  officialLabelEn: "Passport Number",
  type: "text",
  required: true,
  helpKo: "가상 여권의 여권번호를 공백 없이 입력하세요.",
  example: "M12345678",
  validation: { pattern: "^[A-Z0-9]+$", maxLength: 20 },
  sensitive: true,
  aiEditable: false,
  condition: null
}
```

공식 항목의 라벨·필수 여부·순서·선택지는 이 파일 한곳에서 관리한다.

## 16. 오류 및 예외 처리

| 상황 | 기대 동작 |
|---|---|
| 새로고침 | 현재 탭의 작성 상태를 복원하고 마지막 단계로 돌아간다. |
| 탭 종료 | sessionStorage 정책에 따라 데이터가 제거된다. |
| AI 네트워크 오류 | 작성값을 유지하고 `AI 없이 결과 보기`를 제공한다. |
| AI 응답 형식 오류 | 한 번 재시도 후 실패하면 기본 검토로 전환한다. |
| Clipboard API 실패 | 값을 선택 가능한 텍스트로 표시하고 수동 복사 안내를 제공한다. |
| 공식 사이트 링크 실패 | 복사 가능한 공식 URL과 다시 열기 버튼을 제공한다. |
| 조건부 답변 변경 | 하위 값 삭제 여부를 확인하고 모순되는 숨은 값을 남기지 않는다. |
| 필수값 누락 | 해당 섹션과 필드로 이동할 수 있는 오류 목록을 표시한다. |
| 사전 확인 명백한 부적격 | 입력 폼 진입을 차단하고 공식 안내를 제공한다. |
| 사전 확인 판단 필요 | 경고와 공식 링크를 제공한 뒤 사용자가 데모 계속 여부를 결정한다. |
| 실수로 실제 정보 입력 | 자동 탐지의 한계를 고지하며 언제든 전체 삭제할 수 있게 한다. |

## 17. 분석 이벤트

실제 필드 값은 수집하지 않는다. 다음 이벤트 이름과 비식별 상태만 기록할 수 있다.

- `demo_started`
- `precheck_completed` + 결과 유형
- `section_completed` + 섹션 ID
- `validation_failed` + 필드 ID와 오류 유형
- `ai_review_started`
- `ai_review_skipped`
- `ai_review_completed` + 제안 개수
- `result_reached`
- `copy_clicked` + 필드 ID
- `official_site_opened`

공개 데모 초기 버전에서는 외부 분석 도구를 생략해도 된다. 성공 지표는 관찰 테스트로 측정할 수 있다.

## 18. 수용 기준

### AC-01 정상 완료

**Given** 만 18세 이상의 한국 국적 관광객을 가정한 가상 데이터가 있고 90일 이하 여행인 경우  
**When** 사용자가 사전 확인과 모든 필수 섹션을 완료하면  
**Then** 공식 순서의 결과 화면에 도달하고 모든 값에 개별 복사 기능이 표시된다.

### AC-02 명백한 범위 외 조건

**Given** 사용자가 120일 체류 또는 취업 목적을 선택한 경우  
**When** 사전 확인을 완료하면  
**Then** 정보 입력 단계로 넘어가지 않고 이유와 공식 안내 링크를 표시한다.

### AC-03 판단 필요 조건

**Given** 과거 비자 거절 또는 특정 국가 방문 이력을 선택한 경우  
**When** 사전 확인을 완료하면  
**Then** 승인·거절을 단정하지 않고 공식 확인 경고와 계속 여부를 표시한다.

### AC-04 AI 미동의

**Given** 사용자가 AI 검토에 동의하지 않은 경우  
**When** AI 검토를 건너뛰면  
**Then** 신청값을 `/api/review`로 전송하지 않고 기본 결과 화면으로 이동한다.

### AC-05 AI 제안 통제

**Given** AI가 영문 주소 수정안을 반환한 경우  
**When** 사용자가 제안을 아직 승인하지 않았으면  
**Then** 최종 결과에는 원문이 유지된다.

### AC-06 AI 장애 복구

**Given** AI API가 실패하거나 잘못된 JSON을 반환한 경우  
**When** 재시도도 실패하면  
**Then** 작성값은 유지되고 AI 없이 결과를 생성할 수 있다.

### AC-07 세션 저장

**Given** 사용자가 작성 중인 경우  
**When** 같은 탭에서 페이지를 새로고침하면  
**Then** 마지막 완료 단계와 입력값이 복구된다.

### AC-08 전체 삭제

**Given** 현재 탭에 작성 상태가 있는 경우  
**When** `모든 데모 정보 삭제`를 확인하면  
**Then** 화면 상태와 sessionStorage가 초기화되고 랜딩으로 이동한다.

### AC-09 모바일 접근성

**Given** 360px 너비의 모바일 화면과 키보드 탐색 환경에서  
**When** 사용자가 전체 흐름을 진행하면  
**Then** 가로 스크롤 없이 모든 입력·버튼·오류 메시지에 접근할 수 있다.

### AC-10 공식 제출 경계

**Given** 사용자가 결과 화면에 도달한 경우  
**When** 공식 사이트 이동 버튼을 누르면  
**Then** 공식 ESTA 사이트가 새 탭으로 열리고 사진·인증·결제·최종 제출이 공식 사이트에서 필요하다는 안내가 유지된다.

## 21. 출시 체크리스트

- [ ] 실제 개인정보 입력 금지 안내가 랜딩·폼·AI 동의·결과에 보인다.

- [ ] AI의 모든 변경은 사용자 승인이 필요하다.
- [ ] 새로고침 복구와 전체 삭제가 동작한다.
- [ ] 모바일 360px와 PC에서 전체 흐름을 완료할 수 있다.
- [ ] AI 장애 상황에서도 기본 결과를 볼 수 있다.
- [ ] 사진·이메일 인증·결제·최종 제출의 공식 사이트 진행 안내가 보인다.

| 결과 방식 | 공식 항목 순서 + 항목별 복사 버튼 |
| 저장 | 서버 저장 없음, 현재 탭 sessionStorage만 사용 |
| AI 데이터 범위 | 별도 동의 시 전체 데모 신청 내용 검토 |
| AI 필수 여부 | 선택 기능 |
| 신청자 범위 | 만 18세 이상 본인 1명 |
| 자격 분기 | 명백한 범위 외는 중단, 애매한 경우 경고 후 선택 |
| 가격 | 무료 |
| 기기 | 모바일 우선 반응형 웹 |
| 배포 | 외부 링크로 접속 가능한 공개 테스트 버전 |
| 핵심 지표 | 도움 없이 전체 완료하는 비율 |
| AI 수정 | 사용자 승인 후 반영 |
| 디자인 | 토스·애플 같은 미니멀 핵심 중심 스타일 |
| 가칭 | 비자비스(Be Jarvis) |
| 데이터 안전 범위 | 실제 개인정보 금지, 가상 정보 데모 전용 |
| 사진·인증·결제 | 공식 ESTA 사이트에서만 진행 |

## 25. 구현 완료 정의

다음 조건을 모두 만족하면 24시간 MVP 구현이 완료된 것으로 본다.

1. 공개 HTTPS 링크에서 접속할 수 있다.
2. 가상 정보 사용 동의부터 결과 복사까지 중단 없이 완료할 수 있다.
3. 사전 확인의 통과·중단·판단 필요 세 경로가 동작한다.
4. 공식 순서의 모든 MVP 필수 텍스트 항목을 입력·검증·복사할 수 있다.
5. 새로고침 복구와 전체 삭제가 동작한다.
6. AI 검토를 선택하거나 건너뛸 수 있다.
7. AI 제안은 사용자 승인 전에는 적용되지 않는다.
8. AI 실패가 기본 결과 생성을 막지 않는다.
9. 실제 정보 금지·비공식 서비스·승인 비보장 안내가 명확하다.
10. 모바일과 PC에서 테스트 시나리오를 통과한다.
