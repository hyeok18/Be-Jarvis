# 비자비스 개발 우선순위

| 항목 | 내용 |
|---|---|
| 기준일 | 2026-08-24 |
| 기준 문서 | [PRD.md](./PRD.md), [VISION_ROADMAP.md](./VISION_ROADMAP.md) |
| 현재 활성 문제 | 한국 국적 성인의 미국 관광 목적 ESTA 신청 준비 |
| 현재 단계 | 24시간 MVP 구현 준비 |
| 다음 작업 단위 | **WU-01 공식 ESTA 기준 스냅샷과 질문 스키마 확정** |

## 1. 우선순위 원칙

1. 현재 작은 문제인 미국 ESTA 준비를 KPI로 검증하기 전에는 다른 국가나 다른 비자 종류를 제품 기능으로 확장하지 않는다.
2. P0 사용자 흐름을 P1 편의 기능보다 먼저 완성한다.
3. 공식 항목과 분기 기준을 확정한 뒤 UI를 구현한다.
4. AI 없이도 입력·검증·결과·복사가 끝까지 동작해야 한다.
5. 개인정보 보호, 공식기관 비오인, 사용자 승인 없는 AI 수정 방지는 출시를 막을 수 있는 게이트다.
6. 각 작업 단위는 구현과 테스트가 모두 끝나야 완료 처리한다.
7. 한 작업 단위를 완료하면 개발일지를 남기고 다음 세션에서 다음 단위를 시작한다.

## 4. 작업 단위별 완료 조건

### WU-00 — 프로젝트 운영 규칙과 개발일지 체계

산출물:

- 저장소 루트 `AGENTS.md`
- 이 개발 우선순위 문서
- 개발일지 템플릿과 인덱스
- 첫 운영 규칙 개발일지

완료 조건:

- 새 세션의 읽기 순서, 한 번에 한 작업 단위, 테스트 완료 게이트가 명시됨
- 완료·미완료·막힘 상황의 개발일지 규칙이 모두 명시됨
- 다음 작업 단위가 WU-01로 지정됨

### WU-01 — 공식 ESTA 기준 스냅샷과 질문 스키마 확정

목적: 잘못된 공식 항목을 기반으로 UI를 만드는 재작업을 방지한다.

산출물:

- `docs/OFFICIAL_ESTA_SNAPSHOT.md`: 공식 URL, 확인 날짜, 자격·항목·순서·필수 여부
- `public/esta-schema.js`: 설정 기반 전체 질문 스키마
- `public/sample-data.js`: 실제 인물과 무관한 가상 데이터
- 스키마 완전성 검사 스크립트 또는 테스트

검증:

- CBP 공식 ESTA 사이트와 현재 신청 항목 다운로드를 직접 확인
- PRD 8장의 모든 MVP 데이터 그룹이 스키마에 대응되는지 검사
- 필드 ID 중복, 순서 중복, 필수 메타데이터 누락 0건
- 공식 출처로 확정할 수 없는 항목은 `미확정`으로 기록하고 UI 구현을 막음

### WU-02 — 비자 전용 앱 셸·디자인 토큰·상태 구조

산출물:

- 비자 전용 `server.js`, `public/index.html`, `styles.css`, `app.js`
- PRD의 클라이언트 상태 구조
- 토스·애플 방향의 디자인 토큰과 공통 컴포넌트 스타일

검증:

- 서버 시작과 정적 파일 응답
- 브라우저 콘솔 오류 0건
- 모바일 360px에서 초기 화면 가로 스크롤 0건
- 과거 철학 챗봇 문구·프롬프트 잔존 0건

### WU-03 — 랜딩·데모 동의·ESTA 사전 확인

대응 요구사항: FR-001~FR-005, FR-019, AC-02, AC-03.

검증:

- 동의 전 진행 차단
- PASS, STOP, REVIEW 세 경로 테스트
- 범위 외 조건은 입력 폼 진입 차단
- 애매한 조건은 승인·거절을 단정하지 않음
- 공식 사이트 링크와 민간 서비스 고지 확인

### WU-04 — 설정 기반 단계별 폼 엔진과 첫 섹션

산출물:

- `esta-schema.js`를 읽는 재사용 가능한 폼 렌더러
- 이전·다음, 진행률, 오류 위치, 조건부 표시 기반
- 신청자·여권 섹션의 전체 동작

검증:

- 질문 순서를 코드에 중복 하드코딩하지 않음
- 뒤로 이동해도 답변 유지
- 키보드로 첫 섹션 완료 가능
- 모든 입력에 label과 오류 연결

### WU-05 — 전체 ESTA 텍스트 섹션과 조건부 질문

대응 범위: 개인·연락처, 부모·고용, 여행·미국 내 정보, 비상 연락처, 자격·보안 질문.

검증:

- PRD 8장의 지원 데이터 그룹 누락 0건
- 조건부 질문 표시·숨김 동작
- 선행 답변 변경 시 모순되는 하위 값을 사용자 확인 후 제거
- 보안 질문은 AI 추천 없이 공식 영문과 한국어 보조 설명을 함께 표시

### WU-06 — 동기 검증과 입력값 검토 화면

대응 요구사항: FR-007, S05, 테스트 시나리오 6~9.

검증:

- 필수값, 이메일 일치, 날짜 순서, 만 18세, 90일 조건 검사
- 필수 오류가 있으면 결과 생성 차단
- 오류 카드에서 원래 필드로 이동 및 포커스
- AI 호출 없이 모든 검증 동작

### WU-07 — 세션 저장·복원·전체 삭제

대응 요구사항: FR-008, FR-009, AC-07, AC-08.

검증:

- 같은 탭 새로고침 후 단계와 값 복구
- `sessionStorage`만 사용하고 `localStorage`, IndexedDB, 쿠키 미사용
- 전체 삭제 후 상태·저장값 초기화와 랜딩 이동
- 서버·파일 로그에 신청값이 남지 않음

### WU-08 — 결과 카드·복사·공식 사이트 경계

대응 요구사항: FR-013~FR-017, FR-022, AC-01, AC-10.

검증:

- 공식 신청 순서와 결과 순서 일치
- 모든 텍스트 값 개별 복사와 2초 피드백
- Clipboard API 실패 시 수동 복사 제공
- AI 없이 결과 도달 가능
- 공식 사이트는 안전한 새 탭으로 열림
- 사진·이메일 인증·결제·최종 제출 경계 고지

선택 범위: 시간이 허용되면 FR-021 복사 진행 체크를 포함한다.

### WU-09 — 필드 도움 API

대응 요구사항: FR-010, PRD 10.1과 15.4.

검증:

- 요청 크기와 허용 스키마 검사
- API 키가 브라우저에 노출되지 않음
- 신원·보안 질문의 답을 생성하지 않음
- API 실패 시 정적 설명과 예시로 계속 진행
- 요청·응답 본문을 로그에 남기지 않음

### WU-10 — 선택적 AI 전체 검토·제안 승인·장애 대체

대응 요구사항: FR-011~FR-013, AC-04~AC-06.

검증:

- 별도 동의 전 `/api/review` 요청 0건
- `store: false` 적용
- 구조화 응답 스키마 검증과 1회 재시도
- 모든 제안 기본 미선택
- 수락한 제안만 결과에 반영
- API 실패·취소 시 원문 유지와 기본 결과 제공

### WU-11 — 통합·보안·접근성·반응형 검증

대응 범위: 테스트 시나리오 1~18, AC-01~AC-10.

검증:

- 정상·중단·경고·오류·AI 실패 전체 E2E
- 360px 모바일, 태블릿, PC
- 키보드 전체 흐름, label, 포커스, aria-live, WCAG AA 대비
- 브라우저·서버 로그와 네트워크에 금지 데이터가 없는지 확인
- 치명적 항목 매핑 오류와 필수 누락 0건

P0 실패가 하나라도 있으면 WU-12로 진행하지 않는다.

### WU-12 — HTTPS 공개 배포와 출시 점검

산출물:

- 공개 HTTPS 데모 링크
- 실행·배포·데이터 정책이 포함된 README
- 출시 당일 공식 출처 재확인 기록

검증:

- 새 환경에서 설치·실행 재현
- 공개 링크에서 전체 스모크 테스트
- API 키와 `.env` 미커밋
- PRD 21장 출시 체크리스트 전체 통과

### WU-13 — 사용자 테스트 1차와 퍼널 분석

- 목표 사용자와 유사한 성인 5명
- 제공된 가상 정보만 사용
- 진행자 개입 없이 랜딩부터 첫 복사까지 수행
- 완료율, 이탈, 완료 시간, 도움 요청, 자신감, 만족도 기록
- 가장 큰 마찰 한 가지를 WU-14 범위로 확정

### WU-14 — 가장 큰 마찰 한 가지 개선

- WU-13에서 가장 큰 이탈 또는 반복 오류 한 가지만 수정
- 범위를 넓히거나 새로운 비자 기능을 추가하지 않음
- 관련 회귀 테스트와 동일 조건의 재검증 수행

### WU-15 — 사용자 테스트 2차와 KPI 게이트 판정

두 번의 테스트 라운드 결과로 다음을 판단한다.

- 독립 완료율 80% 이상
- 준비 자신감과 경험 만족도 평균 4.0/5 이상
- 필수 누락·치명적 매핑 오류·무승인 AI 수정 0건
- 개인정보·외부 전송·공식기관 오인 안전 사고 0건

모두 만족하면 현재 문제를 `KPI 안정화`로 전환한다. 하나라도 실패하면 다음 문제로 확장하지 않고 가장 큰 실패 원인을 새 작업 단위로 등록한다.

### WU-16 — 다음 작은 문제 재평가

WU-15 KPI 통과 후에만 실행한다. 미국 B1/B2, 다른 미국 목적, 다른 국가 관광 비자, 여권·필수 서류 후보를 `VISION_ROADMAP.md`의 가중치로 다시 점수화하고 한 개만 활성화한다.

## 5. 작업 단위 변경 규칙

- 새로운 필수 작업이 발견되면 기존 ID 사이에 억지로 끼우지 말고 다음 빈 `WU-XX`를 부여한다.
- 긴 작업은 독립적으로 구현·테스트 가능한 하위 단위로 분할한다.
- 우선순위를 바꿀 때는 이유, 영향받는 선행 작업, 변경 날짜를 개발일지에 기록한다.
- 완료된 단위의 범위가 회귀하면 기존 완료 표시를 지우지 않고 회귀 수정 작업 단위를 새로 만든다.
- 현재 `다음` 상태는 항상 하나만 유지한다.

## 6. 현재 인계

다음 세션은 **WU-01**만 수행한다.

시작 순서:

1. 최신 개발일지와 WU-00 기록을 읽는다.
2. 미국 CBP 공식 ESTA 페이지와 신청 항목 다운로드의 현재 접근 가능 여부를 확인한다.
3. 확인 날짜가 포함된 공식 기준 스냅샷을 작성한다.
4. 공식 근거가 확인된 필드만 `esta-schema.js`로 구조화한다.
5. 스키마 완전성 테스트를 통과시킨다.
6. WU-01 개발일지와 인덱스를 갱신하고 세션을 종료한다.
