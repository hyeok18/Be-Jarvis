## 1. 이번 작업의 목표

- 이 작업 단위가 해결하려는 문제: 팀원과 새로운 Codex 세션이 이전 구현 과정과 문제 해결 내용을 놓치지 않고 같은 우선순위로 개발을 이어가게 한다.
- 완료 조건: 저장소 전체에 적용되는 작업 규칙, 의존성 기반 우선순위, 개발일지 템플릿·인덱스·첫 기록이 모두 존재해야 한다.

## 2. 무엇을 만들었는가

- 저장소 루트에 `AGENTS.md`를 추가해 세션 시작, 한 번에 한 작업 단위, 완료 게이트, 개발일지 자동 작성, 다음 세션 인계 규칙을 정의했다.
- PRD의 24시간 구현 순서와 비전 로드맵의 KPI 게이트를 WU-00~WU-16 작업 단위로 재구성했다.
- `DEVELOPMENT_LOG_TEMPLATE.md`에 구현 내용, 문제·막힘, 해결, 검증, 남은 위험, 다음 작업을 기록하는 표준 형식을 만들었다.
- `development-logs/INDEX.md`에 전체 세션이 확인할 상태 인덱스를 만들었다.
- `START_HERE.md`의 새 Codex 읽기 순서와 폴더 구성을 새 규칙에 맞게 갱신했다.

## 3. 무엇이 문제였고 어디서 막혔는가

- 저장소에 기존 `AGENTS.md`가 없어 세션별 구현 범위와 완료 기준을 강제할 규칙이 없었다.
- PRD에는 시간대별 계획이 있었지만 팀 세션이 인계받기 쉬운 독립 작업 단위와 상태 표시는 없었다.
- 기존 인수인계 문서는 제품 맥락은 설명했지만, 새 세션이 이전 실패와 검증 결과를 반드시 읽도록 하는 절차가 없었다.
- 외부 권한이나 사용자 결정 때문에 막힌 항목은 없었다.

## 4. 어떻게 해결했는가

- PRD의 기능 의존성을 기준으로 `공식 스키마 → 앱 셸 → 사전 확인 → 폼 → 검증 → 세션 → 결과 → AI → 품질 → 배포` 순서를 만들었다.
- 비전 로드맵의 원칙에 따라 사용자 테스트 2회와 KPI 통과 전에는 다른 국가나 비자 종류로 확장할 수 없게 했다.
- 완료뿐 아니라 `진행 중`과 `막힘`에도 개발일지를 작성하게 해 다음 세션이 정확한 재개 지점을 찾을 수 있게 했다.
- 현재 작업 완료 후 다음 단위를 같은 세션에서 자동 시작하지 않는 규칙을 추가해 작업 단위별 검증과 인계를 분리했다.

## 6. 남은 위험과 미해결 항목

- 공식 ESTA 신청 항목의 최신성은 아직 이 작업에서 재확인하지 않았다. WU-01에서 반드시 공식 출처로 확인해야 한다.
