## 1. 새 Codex가 처음 할 일

1. 이 `START_HERE.md`를 끝까지 읽는다.
2. `docs/PRD.md`와 `docs/VISION_ROADMAP.md`를 끝까지 읽는다.
3. `data/VISA_COUNTRY_DATABASE.xlsx`의 `요약`, `국가 데이터`, `검증 큐`, `분류 기준`, `출처 로그` 시트를 확인한다.
4. 현재 실제 비자 웹사이트 코드는 아직 구현되지 않았다고 전제한다.
5. 작업 전 공식 ESTA 양식·자격·수수료·필수 항목이 현재도 유효한지 미국 정부 공식 출처로 재검증한다.
6. 아래의 `바로 사용할 Codex 시작 프롬프트`에 적힌 범위부터 구현한다.

문서가 충돌하면 다음 순서로 판단한다.

```text
현재 목적지 정부 공식 출처
→ docs/PRD.md
→ docs/VISION_ROADMAP.md
→ data/VISA_COUNTRY_DATABASE.xlsx
→ starter/의 참고 코드
```

비자 규정은 자주 변경되는 고위험 정보다. 날짜가 오래됐거나 공식 출처가 없는 값은 추측해서 사용자에게 노출하지 않는다.

## 2. 제품의 한 문장 정의

비자비스는 한국어 사용자가 여행에 필요한 비자·전자여행허가 정보를 이해하기 쉬운 형식으로 입력하고, 공식 신청서에 항목별로 복사할 수 있는 결과를 만드는 민간 신청 준비 서비스다.

첫 MVP에서는 한국 국적 성인의 미국 관광 목적 ESTA만 지원한다. 서비스가 신청을 대신 제출하거나 승인 가능성을 판정하지 않으며, 사용자는 최종 신청·여권 사진·이메일 인증·결제·제출을 미국 정부 공식 사이트에서 직접 수행한다.

## 3. 확정된 제품 원칙

- 정확성이 편의성보다 우선이다.
- 한 화면에는 핵심 질문과 다음 행동 하나를 중심으로 배치한다.
- 서비스는 미국 정부·CBP·대사관과 무관한 민간 도구임을 명확히 표시한다.
- 공개 MVP에서는 실제 개인정보 입력을 금지하고 가상 정보만 사용한다.
- 데이터는 서버나 데이터베이스에 저장하지 않고 현재 탭의 `sessionStorage`만 사용한다.
- AI 검토는 선택 사항이다. 동의하지 않은 사용자의 입력은 AI로 전송하지 않는다.
- AI는 누락·형식·번역·답변 간 불일치만 검토한다. 사실, 신원, 여권번호, 보안 답변을 임의로 만들거나 바꾸지 않는다.
- 모든 AI 제안은 사용자가 개별적으로 수락해야 반영된다.
- 결과는 공식 신청 순서의 항목별 복사 카드로 제공한다.
- 자동 제출, 공식 사이트 자동 입력, 승인 예측, 법률 자문은 하지 않는다.
- 국가·국적·여행 목적·신청 경로를 설정 데이터로 분리해 향후 확장할 수 있게 만든다.

## 4. 현재 MVP 범위

### 대상

- 대한민국 국적
- 만 18세 이상
- 본인이 직접 준비
- 미국 관광·휴가·친지 방문 등 허용되는 단기 방문
- 90일 이하 체류
- 대한민국 전자여권 보유

### 핵심 사용자 여정

```text
랜딩
→ 실제 개인정보 금지 및 민간 서비스 동의
→ ESTA 범위 사전 확인
→ 공식 신청서 순서의 단계별 한국어 입력
→ 동기식 누락·형식·날짜 검증
→ 선택적 AI 검토와 제안별 수락/거절
→ 공식 영문 항목명과 값을 항목별로 복사
→ 미국 정부 공식 ESTA 사이트 열기
```

### MVP 비목표

- 실제 개인정보를 받는 운영 서비스
- ESTA 자동 제출·자동 입력·결제·상태 조회
- 승인 또는 입국 가능성 보장
- B1/B2 비자, 취업·유학·이민 비자
- 미성년자·가족·단체 신청
- 회원가입·로그인·결제·영구 저장
- 여권 또는 셀피 업로드와 OCR
- 다국가 사용자 화면 출시

## 5. 국가 비자 데이터의 현재 상태

`data/VISA_COUNTRY_DATABASE.xlsx`는 대한민국 일반여권·관광 목적 기준으로 199개 국가·지역을 정리한 조사 워크북이다.

| 신청 경로 | 국가·지역 수 | 의미 |
|---|---:|---|
| 무사증 | 114 | 비자는 없지만 체류·여권·귀국편 조건 확인 필요 |
| 무사증+입국등록 | 7 | 비자는 없지만 출발 전 또는 입국 시 등록 필요 |
| 전자여행허가(ETA) | 9 | 비자는 아니지만 온라인 사전허가 필요 |
| 전자비자(eVisa) | 26 | 출발 전 온라인 비자 필요 |
| 도착비자 | 9 | 도착 후 발급, 사전 준비 조건 확인 필요 |
| 전자비자/도착비자 | 22 | 두 경로의 자격·비용·입국항 비교 필요 |
| 대사관·영사관 사전비자 | 11 | 출발 전 공관 신청 필요 |
| 특별허가/여행제한 | 1 | 일반 관광비자와 별도 취급 |

이 숫자는 서비스 설계와 검증 우선순위 수립을 위한 현재 스냅샷이다. 외교부 표는 전체 국가 발견용 기준이고, 보조 출처는 분류 후보를 찾는 용도다. 목적지 정부의 공식 출처와 검증일이 모두 있는 `게시 가능` 행만 사용자 화면에 사용할 수 있다.

현재 공식 출처 확인 완료 표시는 미국, 영국, 뉴질랜드, 이스라엘, 중국, 볼리비아, 몽골 7개 국가에만 적용되어 있다. 나머지 행은 `검증 큐`의 P0 → P1 → P2 순서로 확인한다. Passport Index 같은 보조자료를 단독 게시 근거로 사용하지 않는다.

국가 정보 화면을 구현할 때는 `비자 필요/불필요` 두 가지로만 표시하지 말고 다음 경로를 그대로 구분한다.

```text
무사증 / 무사증+입국등록 / ETA / eVisa / 도착비자 /
eVisa·도착비자 선택 / 대사관 사전비자 / 특별허가·여행제한
```

## 6. 폴더 구성

```text
be-jarvis-team-handoff/
├─ START_HERE.md                  # 새 Codex가 가장 먼저 읽을 대표 문서
├─ docs/
│  ├─ PRD.md                     # ESTA 24시간 MVP의 상세 구현 명세
│  └─ VISION_ROADMAP.md          # 큰 문제, 문제 분할, KPI, 확장 순서
├─ data/
│  └─ VISA_COUNTRY_DATABASE.xlsx # 199개 국가·지역 마스터와 검증 큐
├─ previews/                     # 워크북 시트의 빠른 확인용 이미지
├─ scripts/
│  └─ build-visa-country-database.mjs
│                                  # 워크북 생성 원본; Codex 스프레드시트 런타임 필요
└─ starter/
   ├─ server.js
   ├─ start-server.ps1
   ├─ .env.example
   ├─ .gitignore
   └─ public/index.html
                                      # 과거 챗봇의 기술 셸; 비자 UI 구현본은 아님
```

`starter/`는 Node.js 내장 HTTP 서버와 OpenAI Responses API 연결 방식을 참고하기 위한 코드다. 기존 화면 문구와 AI 시스템 프롬프트는 비자비스와 무관하므로 그대로 출시하지 말고 `docs/PRD.md`에 맞춰 교체한다.

`scripts/build-visa-country-database.mjs`는 `@oai/artifact-tool`, 인터넷 연결, 해당 환경의 스프레드시트 런타임을 전제로 한다. 다른 컴퓨터에서 바로 실행되지 않더라도 엑셀의 생성 로직·분류 오버라이드·공식 출처 목록을 확인하는 원본으로 보존한다.
실행 가능한 환경에서 스크립트를 실행하면 결과는 `data/generated/`에 생성된다. `VERIFIED_AT` 날짜는 공식 출처를 실제로 다시 확인한 경우에만 변경한다.

## 7. 권장 기술 구조

24시간 MVP에서는 Node.js 내장 HTTP 서버와 바닐라 HTML/CSS/JavaScript를 사용한다. 데이터베이스와 무거운 프론트엔드 프레임워크는 도입하지 않는다.

```text
/
├─ server.js
├─ start-server.ps1
├─ .env.example
├─ README.md
└─ public/
   ├─ index.html
   ├─ styles.css
   ├─ app.js
   ├─ esta-schema.js
   └─ sample-data.js
```

필수 서버 API는 다음 두 개다.

- `POST /api/field-help`: 특정 항목의 쉬운 한국어 설명과 가상 예시
- `POST /api/review`: 사용자가 명시적으로 동의한 데모 신청값의 구조화 검토

OpenAI API 키는 서버의 `OPENAI_API_KEY` 환경 변수에서만 읽는다. `.env` 파일과 실제 입력값, API 원문 응답, 로그는 저장소에 커밋하지 않는다. 모델과 JSON 응답 계약은 `docs/PRD.md` 10장과 15장을 따른다.

## 8. 기본 구현 순서

1. 공식 ESTA의 현재 자격·항목·순서·필수 여부를 확인하고 출처와 확인일을 기록한다.
2. `starter/`를 새 구현 루트로 복사하거나 같은 구조로 비자 전용 앱을 만든다.
3. `esta-schema.js`에 모든 질문, 공식 영문 라벨, 순서, 조건부 표시, 검증 규칙을 집중시킨다.
4. 랜딩·동의·사전 확인·단계별 폼·검토·복사 결과의 전체 흐름을 AI 없이 먼저 완성한다.
5. `sessionStorage` 복원·전체 삭제·조건부 답변 정리를 구현한다.
6. Clipboard API와 수동 복사 대체 동작을 구현한다.
7. 필드 도움과 전체 검토 AI API를 추가하되, 명시적 동의와 JSON 스키마 검증을 적용한다.
8. 모바일 360px, 키보드 조작, 오류 초점 이동, 명도 대비를 확인한다.
9. `docs/PRD.md`의 수용 기준 AC-01~AC-10과 테스트 시나리오를 실행한다.
10. 가상 정보만 사용한 성인 사용자 5명 테스트를 진행한다.

## 9. 완료 판단 기준

첫 MVP는 다음을 모두 만족해야 완료다.

- 가상 정보로 랜딩부터 복사 결과까지 완료 가능
- 공식 필수 항목 누락과 치명적 매핑 오류 0건
- AI 없이 전체 흐름 완료 가능
- AI 미동의 입력의 외부 전송 0건
- 사용자 승인 없는 AI 수정 0건
- 서버 개인정보 저장 0건
- 공식기관으로 오인될 수 있는 표현 0건
- 모바일과 키보드만으로 핵심 흐름 완료 가능
- 공개 데모 링크에서 재현 가능

제품 단계의 1차 달성은 서로 다른 두 번의 테스트 라운드에서 독립 완료율 80% 이상, 준비 자신감·만족도 평균 4.0/5 이상, 안전 사고 0건을 모두 충족했을 때다.

## 10. 작업 중 반드시 남길 기록

새 Codex나 팀원이 중요한 결정을 변경하면 다음을 문서에 함께 반영한다.

- 변경한 요구사항과 이유
- 확인한 공식 출처 URL과 확인 날짜
- 추가·제외한 범위
- 실행한 테스트와 결과
- 남은 위험과 다음 담당자가 할 일
- 국가 데이터의 경우 `검증 상태`, `최종 공식 출처`, `최종 검증일`, `제품 메모`

## 11. 바로 사용할 Codex 시작 프롬프트

다른 컴퓨터에서 이 폴더 전체를 작업공간으로 연 뒤 다음 문장을 Codex에 입력한다.

```text
이 폴더는 비자비스(Be Jarvis) 팀 프로젝트의 인수인계 패키지다.
START_HERE.md를 가장 먼저 끝까지 읽고, 이어서 docs/PRD.md와
docs/VISION_ROADMAP.md를 끝까지 읽어라. data/VISA_COUNTRY_DATABASE.xlsx의
시트 구조와 게시 가능/게시 금지 규칙도 확인하라.

현재 목표는 대한민국 국적 성인의 미국 관광 목적 ESTA 신청 준비를 돕는
24시간 공개 데모를 구현하는 것이다. 실제 개인정보를 받거나 ESTA를 대신
제출하지 말고, 가상 정보 입력 → 검증 → 선택적 AI 검토 → 공식 항목별 복사
흐름을 완성하라. starter/는 기술 구조 참고용이며 기존 문구와 프롬프트는
비자비스 구현이 아니므로 PRD에 맞게 교체하라.

구현 전에 현재 미국 정부 공식 ESTA 정보와 신청 항목을 공식 출처로 재확인하고,
확인한 URL과 날짜를 기록하라. 그다음 PRD의 24시간 구현 계획과 AC-01~AC-10을
기준으로 구현·테스트하라. 작업공간에 기존 변경이 있으면 보존하고, 완료 후에는
구현 결과, 테스트 결과, 남은 위험, 다음 팀 작업을 요약하라.
```

## 12. 전달 시 제외한 항목

다음은 비자비스 인수인계에 필요하지 않거나 보안·용량상 제외했다.

- `.env`와 API 키
- 서버 로그
- Node.js 포터블 런타임과 `node_modules`
- 엑셀 내부 검수용 대용량 `inspect.ndjson`
- 비자비스와 무관한 초기 아이디어·인터뷰·챗봇 문서
- 임시 PDF 렌더링 파일

새 컴퓨터에서는 자신의 환경 변수와 Node.js 런타임을 사용한다. 어떤 실제 비밀값도 이 폴더에 추가해 공유하지 않는다.
