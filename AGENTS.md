# Repository Guidance

## Current phase

This repository is in product discovery for a 24-hour hackathon build. Treat `PRD.md` as the implementation contract after it is created. Until then, do not infer additional product scope from the legacy repository history.

## Source of truth

- `PRD.md`: final requirements and acceptance criteria after the interview
- `docs/PROJECT_CONCEPT.md`: provisional product idea, not a final specification
- `README.md`: project orientation and status

## Scope discipline

- Optimize for a working end-to-end demo within 24 hours.
- Keep required, deferred, and out-of-scope features separate.
- Do not classify a review as fraudulent from a single statistical or language signal.
- Preserve raw review data separately from derived scores.
- Make every adjusted score explainable in the user interface.

## Verification

When implementation begins, every user-visible requirement must have a concrete acceptance criterion and a reproducible verification step.
