## 1. 이번 작업의 목표

- 해결하려는 문제: 구현 코드와 품질 게이트가 없고 Supabase·Vercel 연결 대상과 안전한 실행 순서가 문서에 충분히 고정되지 않았다.
- 세션 범위: 플러그인으로 현재 리소스를 읽기 전용 확인하고, PRD·AGENTS에 DB·배포 계약을 추가한 뒤 Next.js App Router + TypeScript + Tailwind 앱 셸과 자동 검증 명령을 구현한다.
- 완료 조건: 환경변수 템플릿과 오류 경계를 포함한 앱 셸이 존재하고 `lint`, `typecheck`, `test`, `build`가 모두 성공해야 한다.
- 범위 밖 항목: Supabase project 생성·DDL·seed·RLS 적용, Vercel project 생성·Preview/Production 배포.

## 2. 무엇을 만들었는가

- Next.js 16 App Router, React 19, TypeScript, Tailwind CSS 기반 프로젝트를 저장소 루트에 구성했다.
- 한국어 메타데이터, 반응형 랜딩 앱 셸, 합성 리뷰·자동 분석 비판정 고지, 로딩·404·일반 오류·전역 오류 경계를 구현했다.
- `/api/health` 상태 확인 경로와 `.env.example`의 8개 환경변수 이름 계약을 만들었다.
- ESLint, TypeScript, Vitest, Next production build, 환경 계약 검사 스크립트와 pnpm 잠금·빌드 허용 정책을 고정했다.
- Supabase migration·RLS·명시적 GRANT·인덱스·동시성 원칙과 Vercel Local→Preview→Production 배포 게이트를 PRD와 AGENTS에 추가했다.
- 플러그인 연결 상태를 읽기 전용 확인해 기존의 관련 없는 Supabase 프로젝트를 재사용하지 않고, 신규 자원 생성은 비용·대상 승인 후 WU-03과 WU-18에서 수행하도록 기록했다.

## 3. 무엇이 문제였고 어디에서 막혔는가

- `create-next-app` 첫 실행은 하위 프로세스가 Node를 PATH에서 찾지 못해 실패했다.
- 번들 Node를 PATH에 추가한 두 번째 실행은 임시 application path 쓰기 가능성 검사에서 실패했다.
- 초기 의존성 해석에서 ESLint 10·TypeScript 7이 Next ESLint 플러그인의 peer 범위를 벗어났고, pnpm의 엄격한 dependency build 정책이 `unrs-resolver` 스크립트를 미승인 상태로 탐지했다.
- 첫 Vitest 실행은 CommonJS로 읽힌 TypeScript 설정에서 ESM 경고를 냈다.
- 브라우저 오류 오버레이·빈 화면 검사 표현식 두 개는 PowerShell과 하위 `cmd`의 따옴표·리다이렉션 해석 때문에 각각 한 번 실패했다. 앱 자체 실패는 아니었다.
- axe 검사는 CSS 그라디언트 때문에 11개 텍스트 노드의 색 대비를 자동 판정하지 못해 `incomplete` 1건으로 묶었다.
- 외부 작업의 막힘: 저장소 전용 Supabase 프로젝트와 Vercel 프로젝트가 아직 없다. 현재 확인된 Supabase 프로젝트 2개는 다른 용도이고 Vercel 프로젝트는 0개다.

## 4. 어떻게 해결했는가

- 생성기를 반복 실행하지 않고 공식 Next.js 파일 구조와 설정 계약을 기준으로 필요한 파일을 명시적으로 작성했다.
- ESLint를 `9.39.5`, TypeScript를 `6.0.3`으로 고정해 peer 검사를 통과시켰다.
- `pnpm-workspace.yaml`에서 `unrs-resolver`의 build를 명시적으로 거부해 임의 설치 스크립트를 승인하지 않으면서 재현 가능한 설치를 만들었다.
- `package.json`에 `type: module`을 선언해 Vitest 설정 경고를 제거했다.
- 브라우저 검사는 셸에 안전한 단순 DOM 표현식과 agent-browser의 `errors`, `console`, `a11y` 명령으로 다시 수행했다.
- muted 텍스트 색상을 `#476168`로 어둡게 조정했다. 그라디언트 최대 혼합 배경 `#d8e9e7` 기준 대비는 muted 5.26:1, accent 6.09:1, 본문 12.62:1로 수동 계산해 WCAG AA 일반 텍스트 기준을 넘겼다.
- 원격 자원은 사용자 조직·리전·비용·대상 확인 없이는 만들거나 연결하지 않는 승인 게이트로 분리했다.
